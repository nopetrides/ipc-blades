## What this project is

MBC is the Phase-2 Unity artifact for the thesis *"To what extent do representative real-time
VR contact models reproduce the observable mechanical coupling of a controlled, maintained
edge-on-edge blade bind?"* It is **not** a game and **not** a VR user study. It is a controlled
comparison of contact models against a physical reference, delivered in a VR-capable project.

The physical reference and its analysis live in the parent **Thesis** repository: the trial review
in `Workspace/Week3/Checkpoint_3_Post_Recording_Review.md`, and the supervisor's direction for this
phase in `Workspace/Week3/Checkpoint_3_Notes.md`. This Unity project is included there as a git
submodule.

## Research discipline — record · validate · justify

This is a **research artifact, not a game.** Every design / engineering / method choice recorded in
these docs (or built in `Assets/P3T/`) must be:

1. **Recorded** — here and in the Thesis Journal (`Workspace/ThesisJournal.md`).
2. **Validated against the research question / hypothesis** — does it serve the reproduction/fidelity
   comparison, or is it artifact polish?
3. **Justified** — with a citation to the verified corpus (`Workspace/**/ReferencePDFs`), a
   documented primary-researcher decision, or Bill's supervisory steer. **"Because that's how I build video games" is not a justification.**

Anything that affects **analysed results** must be justified and cited *before* it enters the data.
Interactive-demo-only engineering is allowed but disclosed as demo (never analysed). Artifact/demo
progress is not a finding.

## Folder conventions

- `Assets/Docs/` — these design docs (this folder).
- `Assets/MBC/` — **project-owned** code, scenes, prefabs, materials. New work goes here.
- Third-party and Unity-template assets stay where the importer put them and are **not edited in
  place**; wrap or subclass under `Assets/MBC/` instead, and disclose in
  [01_ComparisonOverview.md](01_ComparisonOverview.md#third-party-provenance).

`.meta` files for these docs are generated by the Unity editor on next import; commit them with
the docs so asset references stay stable.

## How to keep these alive

When you change a joint parameter, a model definition, a metric, or the run-mode split, update
the relevant doc **in the same commit** and add a dated line to its changelog. Each doc ends with
a changelog for exactly this purpose.
